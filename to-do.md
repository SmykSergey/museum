**Статус:** ✅ выполнен

## Этап 1. Каркас Django

- `django-admin startproject config .` внутри `museum/`
- Разделение `settings/` на `base.py`, `dev.py`, `prod.py` — чтобы локально и на сервере были разные конфиги
- Структура приложений:

```
museum/
├── venv/
├── config/            # настройки проекта
├── apps/
│   ├── core/          # главная страница, общие вещи
│   ├── news/          # новости
│   ├── events/        # события (+ архив)
│   └── locations/     # 4 локации: адреса, график, цены
├── templates/         # HTML → Django-шаблоны
├── static/            # style.css, ph/, js
└── locale/            # переводы uk/en
```

- **Проверка:** `python manage.py runserver` → открывается заглушка Django

## Этап 2. Модели данных

- **Location:** название, адрес, график работы, цены (rich-text), фото, порядок вывода
- **NewsItem:** заголовок, описание, фото, дата публикации, активность
- **Event:** заголовок, описание, дата события, локация (FK), архивный флаг
- Поля под i18n сразу (или переводимые модели — решим на месте, обсудим)
- Миграции, тестовые данные (fixture)
- **Проверка:** модели видны в shell, миграции применяются

## Этап 4. Шаблоны и страницы

- Порт вёрстки в `templates/`: `base.html` (шапка/меню/переключатель языка) + страницы
- Главная: локации, события, новости — тянутся из БД вместо захардкоженных карточек
- Страницы: список новостей, детальная новость, список событий, архив, страница локации
- Пагинация для списков
- **Проверка:** то, что добавили в админке, отображается на сайте

## Этап 5. Мультиязычность (uk/en)
