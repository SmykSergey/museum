## Этап 4.7. API и киоск

Киоск (сенсорный стол, 1280×1024) — отдельный продукт, но данные для него
теперь берутся с сайта. Это решение принято, чтобы не держать три копии
контента: `heroes-data.json` на сайте, `heroes.json` в макете и
сгенерированный HTML киоска.

**Что сделано:**

- `apps.api` — read-only API `/api/v1/`: `ping`, `branches`, `districts`,
  `heroes`, `heroes/<slug>`, `sync`. Сжатие gzip, `ETag`/304,
  `?since=<версия>` для дешёвой проверки «ничего не изменилось».
- `apps.api.manifest` — манифест файлов с sha256 и кэшем по (размер, mtime),
  чтобы не хешировать 178 МБ на каждый запрос.
- `apps.kiosk` — сборка офлайн-бандла: `python manage.py build_kiosk`.
  Генерирует 500 карточек героев, списки по родам войск, `soldiers_data.js`,
  `data.json`, `sync.json`, сжимает фото и проверяет битые ссылки.
- Карты районов перенесены в `static/maps/` и отдаются API.
- Модель: добавлено поле `Hero.period` (`2014` / `2022`).

**Проверка:** 130 тестов, сборка 500 героев без битых ссылок,
sync 968 КБ → 113 КБ по gzip.

- `GET /api/v1/bundle/` — готовый архив киоска для скачивания.
- `scripts/kiosk_sync.py` — синхронизация на стороне стола: сравнивает версию,
  скачивает архив, распаковывает, делает резервную копию. Работает без
  зависимостей, только стандартная библиотека Python.
- `docs/kiosk-guide.md` — гайд по ручному и автоматическому обновлению.

**Проверка:** сборка 500 карточек, синхронизация скачала и распаковала бандл,
повторная проверка отвечает «обновление не требуется», битых ссылок нет.

**Осталось:**

- перенести раздел 2014–2021 в новую модель (сейчас 155 старых HTML-страниц
  лежат в `museum_page/old/` и копируются в бандл как есть — это 111 МБ);
- при переносе киоска на новый дизайн заменить сгенерированные HTML-страницы
  на JS-клиент, читающий `data.json` (тогда синхронизация будет дельта-обменом,
  а не скачиванием архива).
