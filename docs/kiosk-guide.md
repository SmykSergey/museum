# Гайд: как обновлять данные и киоск

Коротко: **сайт — единственный источник данных**. Всё, что вы добавляете в
админке сайта, попадает в киоск после одной команды сборки.

---

## 1. Общая схема

```
   АДМИНКА САЙТА                    БАЗА                       КИОСК (стол)
  добавляете героя   ────────►   Django + PostgreSQL   ────────►  папка с HTML,
  (фото, биография)                                          фото и data.json
                                        │
                                        │  build_kiosk
                                        ▼
                                  архив kiosk.zip
                                  (его скачивает стол)
```

- **Сайт** — мастер-копия. Правите только здесь.
- **Киоск** — офлайн-копия. Интернет ему нужен только на время синхронизации.

---

## 2. Как добавить героя

1. Откройте админку: `https://<адрес сайта>/admin/`.
2. Раздел **«Герої не вмирають» → «герої»** → кнопка **«Додати героя»**.
3. Заполните:
   - **ПІБ** — как в документах: `Шевченко Тарас Григорович`;
   - **звання та дати** — строкой в скобках: `(01.01.1980 – 02.02.2023)`;
   - **період** — `2022 – ....` или `2014–2021`;
   - **рід військ** — из списка (можно добавить новый в разделе «роди військ»);
   - **район Одещини** — нужен для карты района в киоске и для фильтра на сайте;
   - **біографія** — каждый абзац с новой строки;
   - **опубліковано** — галочка.
4. В блоке **«Фото героя»** внизу страницы загрузите фотографии.
   **Первое по порядку фото становится главным** — оно показывается в карточке.
5. Сохраните.
6. **Ідентифікатор** (адрес страницы) можно не заполнять — он создастся сам из
   ПІБ транслитерацией (`Shevchenko_Taras_Hryhorovych`).

Проверьте результат на сайте: `https://<адрес сайта>/geroi/`.

> Если герой добавлен «заздалегідь», снимите галочку «опубліковано» — он не
> попадёт ни на сайт, ни в киоск.

---

## 3. Как обновить киоск вручную

Это основной способ. Нужно 2 шага: собрать свежий архив на сервере и
перенести его на стол.

### 3.1. Собрать архив на сервере

```bash
cd backend
python manage.py build_kiosk --zip
```

Результат:

- `dist/kiosk/` — готовая папка;
- `dist/kiosk.zip` — тот же набор одним архивом (~58 МБ без раздела 2014–2021).

Полезные варианты:

```bash
python manage.py build_kiosk --zip --no-legacy   # без раздела 2014–2021 (вдвое меньше)
python manage.py build_kiosk --zip --clean       # собрать с нуля
python manage.py build_kiosk --photos original   # не сжимать фото (будет ~170 МБ)
```

В конце команда пишет, сколько героев и фото попало в сборку и есть ли
битые ссылки. **Хорошая сборка — «битых ссылок нет».**

### 3.2. Перенести на стол

**Вариант А — флешка / копирование по сети:**

1. Скопируйте `dist/kiosk/` на стол, заменив старую папку целиком.
2. На столе откройте `index.html` (или перезагрузите страницу, если браузер
   уже открыт).

**Вариант Б — через сам сайт (если стол в сети):**

Архив уже лежит на сайте по адресу `/api/v1/bundle/`. Можно просто скачать
его через браузер на столе и распаковать поверх папки киоска.

## 4. Как обновлять киоск автоматически

Если стол в интернете, синхронизацию можно делать скриптом — он сам проверит,
изменились ли данные, и скачает только если нужно.

### 4.1. Скрипт

В репозитории: `scripts/kiosk_sync.py`. Нужен только Python 3.8+, ничего
устанавливать не надо.

Положите его на компьютер рядом со столом (или на сам стол) и запустите:

```bash
python kiosk_sync.py --api https://<адрес сайта> --dir D:/kiosk
```

Что он делает:

1. спрашивает у сайта версию данных;
2. сравнивает с версией в папке киоска (`sync.json`);
3. если версии разные — скачивает `/api/v1/bundle/` и распаковывает;
4. старую версию сохраняет в `D:/kiosk_backup/<версия>/`.

Проверка без скачивания:

```bash
python kiosk_sync.py --check
```

### 4.2. Запуск по расписанию

**Windows:** «Планировщик заданий» → «Создать задачу» → ежедневно →
«Запуск программы»:

```
Программа:  python
Аргументы:  C:\museum\kiosk_sync.py --api https://<адрес сайта> --dir D:\kiosk
```

**Linux:** `crontab -e`

```
0 6 * * * cd /opt/museum && python3 scripts/kiosk_sync.py --api https://<адрес сайта> --dir /opt/kiosk >> /var/log/kiosk_sync.log 2>&1
```

> Если интернета на столе нет — этот раздел пропускайте, обновляйте вручную
> (раздел 3). Киоск продолжит работать на последней скачанной версии.

---

## 5. Настройка стола

1. Папка киоска лежит локально, например `D:\kiosk`.
2. Браузер открывается на `file:///D:/kiosk/index.html`.
3. Включите полноэкранный режим киоска:
   - Chrome/Edge: `--kiosk file:///D:/kiosk/index.html --start-fullscreen --disable-pinch`;
   - либо F11 после открытия.
4. Разрешение экрана — **1280×1024**, масштаб 100%.
5. Отключите заставку и спящий режим.

## 6. Если нужно загрузить данные из архива заново

Когда фото и JSON лежат в папке `museum_page/` (или в её копии на сервере):

```bash
cd backend
python manage.py import_heroes --data ../museum_page/heroes.json --photos ../museum_page/2022
```

Команда:

- чистит BOM в именах (иначе ломается сортировка и алфавит);
- создаёт отсутствующих героев и обновляет существующих по `id`;
- пересобирает галереи;
- **не удаляет** героев, которых нет в JSON.

Проверить, что получилось, без записи в базу:

```bash
python manage.py import_heroes --dry-run
```

Если фото уже лежат в `media/` и архив не нужен:

```bash
python manage.py import_heroes --skip-photos
```

## 7. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| `Папка с фото не найдена` | не распакован архив фото | указать `--photos ПУТЬ` или `--skip-photos` |
| В киоске нет нового героя | сборка не пересобрана | `python manage.py build_kiosk --zip` и скопировать заново |
| Фото в киоске не открывается | файл был пустой при импорте | перезапустить `import_heroes --photos ...` — пустые файлы перезапишутся |
| `build_kiosk` пишет «битых ссылок» | не найден статичный файл | смотреть список в выводе команды |
| Портал в киоске не открывает 2014–2021 | сборка сделана с `--no-legacy` | собрать без флага |
| Сайт не подключается к БД | порт занят другим проектом | проверить `POSTGRES_PORT` в `.env`, поднять контейнер на свободном порту |

## 8. Чек-лист обновления

- [ ] Изменения внесены в админке сайта
- [ ] На сайте всё отображается правильно (`/geroi/`, карточка героя)
- [ ] `python manage.py build_kiosk --zip` — «битых ссылок нет»
- [ ] Папка `dist/kiosk/` или архив `dist/kiosk.zip` перенесены на стол
- [ ] На столе открылся `index.html`, проверить: список, поиск, карточку героя, карту района

## 9. Справочник API (для разработчика)

| Метод | Что отдаёт |
|---|---|
| `GET /api/v1/ping/` | версия данных, счётчики |
| `GET /api/v1/branches/` | роды войск |
| `GET /api/v1/districts/` | районы + ссылки на карты |
| `GET /api/v1/heroes/?period=2022&branch=3&district=Одеський&q=Іван&limit=50` | список |
| `GET /api/v1/heroes/<slug>/` | карточка героя |
| `GET /api/v1/sync/` | полный набор + манифест файлов (sha256) |
| `GET /api/v1/bundle/` | готовый архив киоска |

Поддерживается `ETag` / `If-None-Match` (ответ 304) и `?since=<версия>`
(ответ `{"not_modified": true}`) — чтобы не качать данные зря.
